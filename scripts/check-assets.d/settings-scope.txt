# 1 文字目が # の行と空行は無視する（行頭の空白は剥がさない）。UTF-8（BOM なし）・LF で保存する。
#   両版はこのファイルを検査対象のツリーではなくスクリプト自身の位置（check-assets と同じフォルダの check-assets.d/）から読む
#   （publish-share は .claude/ だけを取り出した一時ツリーを検査させるため）。表は両版のコードにはもう無いので、表を更新するときは
#   このファイルだけを直す。区分の意味・根拠（settings-reference の Scope 欄）と照合の仕方は check-assets.sh の 3. の冒頭にある。
#
#   書式: タグ<TAB>値（行頭のタグで値の意味が決まる）
#     format<TAB>1   … スキーマ版。最初のデータ行に 1 回だけ書く（読み手は版 1 を期待する）。行を足す・消す・直すだけでは上げず、
#                      タグや値の意味を変えるときだけ上げる（そのときは両版の読み手も同時に直す）
#     u<TAB>キーパス  … U = user / local / managed / --settings でのみ有効なキー（project の .claude/settings.json では無視される）
#     m<TAB>キーパス  … M = managed 専用のキー（project でも --settings でも無視される）
#     e<TAB>選択肢    … E = env のうち project / local からは設定できない変数名を表す正規表現の選択肢（1 行 1 個）。両版は全行を
#                      | で結び、^( と )$ で包んで変数名の全体に照合する
#     wtool<TAB>ツール名 … 照合されない権限ルールのツール名（パス付きのルール「ツール名(…)」がどこに置いても効かないもの）。両版は
#                      全行を | で結んで ( ) で包み、「( ) の中が 1 文字以上」を表す部分（コードにある）を後ろに付けて、ルールの全体に
#                      照合する（大文字小文字を区別する）
#   キーパスは英数字と _ の名前を . でつないだもの（a.b.c。各段の名前を大文字小文字を区別して照合する。値は見ない）。ツール名は
#   英数字と _ だけ。u / m の行の順が、WARN に並ぶキーの順になる。
#   u / m に載せるキーの基準: settings-reference の表で Scope が `Any file` / `Global config` 以外のキーは全量（issue #5 の I-2。
#   2026-11-03 裁定。基準の正式な検討は別途）。Scope が `Managed` のキーは m、それ以外（`User or managed`・`User, local, or managed`・
#   `User`）は u に置く（--settings でも無視されると docs が書くキーは m。M 節のコメント）。追随では表の Scope 列の差分だけを見る。
#   入れ子のキーは親が載っていれば親で拾われる（check-assets の照合はキーパスの前方一致。表のキーパスを settings.json で 1 段ずつ
#   たどれれば該当とする）ので、親が載っている入れ子のキー（autoMode.classifyAllShell・policyHelper.*・strictPluginOnlyCustomization.*）
#   は足さない。
#   書式の誤り（未知のタグ・列の数が 2 でない・空の値・値に使えない文字・同じタグの中での重複・format 行の欠落 / 重複 / 版の違い・
#   format 行より前のデータ行・u / m / e / wtool のどれかの行が 1 つも無い・NUL バイト）が 1 つでもあれば、check-assets は FAIL に
#   して settings.json のキーの検査をしない（検査器自身の表が欠けた状態を PASS にしない）。
#
#   e の選択肢を書くときの注意:
#     - 使える文字は英数字・_ と . * ( ) | ? だけ。エスケープ（バックスラッシュ）や [ ] { } + ^ $ は使わない。照合の二段階目は、
#       選択肢から組み立てた正規表現そのものも A〜Z を小文字に畳んで照合する。バックスラッシュ ＋ D・S・W・B のように大文字と
#       小文字で意味が違うエスケープを含むと、畳んだときに意味が変わる。リテラルと . * ( ) | ? だけなら畳んでも意味は変わらない
#     - ( ) は釣り合わせる。| は ( ) の中でだけ使う（括弧の外の | は 1 行に 2 個の選択肢を書いたことになる）。* と ? は英数字・_・
#       .・) の直後にだけ置く（python の re と .NET のどちらでも組み立てられる形に限る。読み手が検査する）
#     - 照合は二段階: 完全一致（大文字小文字を区別）→ 一致しなければ A〜Z だけを小文字に畳んだ同士。大文字小文字だけが違う変数名
#       （systemroot 等）は別の文言の WARN になる（環境変数名の大文字小文字を区別しないのは Windows だけ）
