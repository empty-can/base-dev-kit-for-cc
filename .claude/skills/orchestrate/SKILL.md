# オーケストレーション・フレームワーク

このスキルは、複数の Sub-agent を協調させて複雑なタスクを効率的に処理する手順を提供します。

Sub-agent は v2.1.172 以降、既定で自分の Sub-agent を起動できます（既定はメイン会話から 3 層まで。
`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` で変更可）。ただし対話セッションでは入れ子の中間出力はメイン会話に
返らず、最上位 Sub-agent の要約だけが返るため、役割分担や段階的処理を設計して協調させる本スキルは
**メインセッション**で実行し、`Agent` ツール経由で子エージェントを並列/順次起動します。

メイン会話から起動した子エージェントは既定で **background** で動き、fork モード（既定で有効）の間、
対話セッションの Claude はその場で完了を待てません。結果は後のターンに**完了通知**として届きます。そのため
パターン A・C の統合は全員分の完了通知が揃ってから、パターン B の次段は前段の完了通知を受け取ってから
起動します（通知が届く前に結果を推測して先へ進まない）。完了を待たせたいときは、Claude Code の起動前に
OS の環境変数（キットのランチャーを使うなら `.claude/custom.env`）で `CLAUDE_CODE_FORK_SUBAGENT=0` を設定すると、
待つよう頼めば待つようになります。`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` でもすべての子エージェントを
待つようになりますが、Bash / PowerShell の background 実行と Ctrl+B も止まります。

## パターン A: 並列調査（Parallel Research）

複数の独立したトピックを同時に調査する場合に使用します。

**手順**:
1. タスクを独立したサブトピックに分割
2. 1 メッセージで複数の Agent ツール呼び出しを並列実行
3. 全エージェントの結果が揃った後に統合・分析

**例**: 「認証方式 A と B を同時に調査して比較」

## パターン B: 段階的処理（Sequential Chain）

前段の結果が次段の入力になる場合に使用します。

**手順**:
1. Phase 1: Explore エージェントでコードベースを調査
2. Phase 2: Plan エージェントで実装計画を策定（Phase 1 の結果を渡す）
3. Phase 3: code-reviewer エージェントで成果物をレビュー

**例**: 「既存コードを調査してからリファクタリング計画を立案」

## パターン C: 役割分担（Divide and Conquer）

大規模タスクを専門領域に分割して並列処理する場合に使用します。

**手順**:
1. タスクを専門領域（フロントエンド・バックエンド・テスト等）に分割
2. 各領域を専門エージェントに並列割り当て
3. メインセッションが全結果を取りまとめて統合

**例**: 「フロントエンドとバックエンドの変更を同時に実装」

## 実行のガイドライン

- **並列化できるものは並列化する**: 1 メッセージで複数 Agent ツール呼び出しを行う
- **コンテキストを明示して渡す**: 子エージェントはメインの会話コンテキストを持たないため、必要情報をプロンプトに含める
- **結果の統合はメインセッションで**: 子エージェントの出力を受け取り、最終的な判断と統合はメインセッションが担う
